# Test Strategy

The test suite was created after the implementation phase. Each level uses the source artefacts prescribed by the experiment protocol.

| Level | Source artefacts | Why it is appropriate | Main coverage |
| --- | --- | --- | --- |
| Unit | Specification and implementation | Isolates deterministic rules and adapters whose edge cases are faster and clearer without HTTP or process state. | Normalization, schema limits, challenge signing/expiry/tampering, runtime configuration, configurable-option reload, atomic JSON integrity, spreadsheet neutralization, workbook structure, and MIME email content/attachment. |
| API/contract | Specification and Acceptance Criteria | Verifies the public REST shapes, statuses, headers, authentication, and validation independent of browser code. | Both form contracts, registration success/idempotency/conflict, field/option/consent errors, content type/size, origin/honeypot, export authorization/content, health, throttling, and security headers. |
| Integration | Specification and Acceptance Criteria | Exercises interactions where correctness depends on transaction, filesystem, concurrency, restart, or worker state rather than one function. | Database plus JSON correlation, rollback on backup failure, concurrent submissions, restart persistence, durable outbox success, and SMTP-failure recovery. |
| Acceptance/component | User Stories and Acceptance Criteria | Checks that participant-visible frontend structure and state transitions implement the stated outcomes without duplicating backend internals. | Fixed variants are API-tested; static component checks cover semantic fields/groups, backend-gated confirmation, safe rendering, retry state, keyboard focus affordances, responsive layout, and reduced motion. |
| Security/negative | Project constraints, Specification, and Acceptance Criteria | Production protections require explicit hostile and malformed inputs rather than only happy-path examples. | Challenge tampering/expiry, origin mismatch, honeypot, throttling, unknown/inactive options, unexpected fields, control characters, payload/media limits, export denial, formula injection, safe response headers, and production-setting rejection. |
| Regression/edge/failure | User Stories, Acceptance Criteria, and Specification | Preserves behaviour most likely to regress when programme configuration or infrastructure changes. | Unicode/whitespace, empty option selection/export, configuration reload with fixed-field stability, idempotent retry, concurrent IDs/backups, invalid storage, worker retry, and persisted state after restart. |

The HTTP tests call the ASGI interface directly with complete request scopes, avoiding an external port while still traversing middleware, routing, request parsing, exception handling, response serialization, and lifespan setup. PostgreSQL-specific deployment is additionally checked through migrations and the container configuration during verification; SQLite is used for deterministic isolated test databases.
