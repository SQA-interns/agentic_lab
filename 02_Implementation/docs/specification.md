# Technical Specification — Conference Registration System

Inputs: `01_Input_Files/*` (frozen). Acceptance criteria: `docs/acceptance-criteria.md`.
Every section lists the acceptance criteria (AC) it realises. Technology is fixed by
`TECH_STACK.md`; this document only decides what that file leaves open.

---

## 1. Architecture overview

```
 Browser ──HTTP──> frontend container (Nginx, non-root, :8080)
                    ├── /            static React SPA (Vite build)
                    └── /api/*       reverse proxy ──> backend container (Spring Boot, non-root, :8080)
                                                         ├── PostgreSQL 16 (db container, named volume)
                                                         ├── /data/backups  (named volume, JSON backups)
                                                         ├── /config/conference-options.json (bind mount, US-003)
                                                         └── SMTP server (external, configured by env)
```

* Frontend and backend are separate deployables; the only coupling is the REST API
  (PC §Frontend/backend communication). The SPA calls relative `/api/...` URLs; Nginx
  proxies them, so the browser sees a single origin and no CORS is needed.
* Backend: Spring Boot 3 / Java 21, **layered architecture** — chosen over hexagonal because
  the domain is small (one aggregate, CRUD-like) and layering is directly enforceable with
  ArchUnit:

| Package (`org.conference.registration.*`) | Responsibility | May depend on |
|---|---|---|
| `api` | REST controllers, request/response DTOs, exception handler, web filters | `service`, `domain`, `config` |
| `service` | Registration use case, option catalog, anti-bot token, rate limiter, backup writer, mail notifier, Excel exporter | `repository`, `domain`, `config` |
| `repository` | Spring Data JPA repositories | `domain` |
| `domain` | JPA entities, enums, value objects | nothing internal |
| `config` | `@ConfigurationProperties`, security config, Jackson/async config | `domain` (and `api` only for filter wiring in `SecurityConfig`) |

  Rules (ArchUnit, executable): no layer depends on a layer above it; `repository` never on
  `service`/`api`; `service` never on `api`; `domain` depends on no other application package;
  no package cycles.

## 2. Data model (AC-005-01, AC-005-06, AC-003-*)

### 2.1 Relational schema (Flyway `V1__init.sql`, `ddl-auto=validate`)

`registration`

| column | type | notes |
|---|---|---|
| `id` | `uuid` PK | generated by the application |
| `type` | `varchar(16)` not null | `EXTERNAL` / `STUDENT` (check constraint) |
| `first_name`, `last_name` | `varchar(100)` not null | |
| `email` | `varchar(254)` not null | stored as entered (trimmed) |
| `organization` | `varchar(200)` null | required iff `EXTERNAL` (check constraint) |
| `study_institution`, `study_programme` | `varchar(200)` null | required iff `STUDENT` |
| `student_id` | `varchar(50)` null | required iff `STUDENT` |
| `privacy_consent` | `boolean` not null | always `true` for stored rows (check constraint) |
| `created_at` | `timestamptz` not null | |
| `backup_file` | `varchar(255)` not null | file name of the JSON backup |

`registration_option` (`registration_id` FK → `registration` ON DELETE CASCADE,
`option_id varchar(64)`, `category varchar(16)`, `display_name varchar(200)`,
PK (`registration_id`, `option_id`)). The display name is snapshotted so later
configuration changes do not rewrite historical registrations.

Index: `registration(created_at)` for export ordering. Encoding UTF-8 (Postgres default in
the official image) — AC-001-07.

### 2.2 JPA

`Registration` entity with `@ElementCollection` of embeddable `SelectedOption`
(`optionId`, `category`, `displayName`). `RegistrationType` and `OptionCategory`
(`WORKSHOP`, `EVENT`, `MEAL`, `ACTIVITY`) enums stored as strings.

## 3. Configurable options (US-003, AC-003-01…07, AC-002-06/07)

* Source: JSON file whose path is `app.options.file` (env `APP_OPTIONS_FILE`), default
  `classpath:conference-options.json`. In the container it is bind-mounted at
  `/config/conference-options.json`, so organizers change options by editing that file and
  restarting the backend — no code or fixed-field change (AC-003-02). No admin UI (out of scope).
* Format:

```json
{ "options": [
  { "id": "ws-secure-coding", "category": "WORKSHOP", "name": "Secure coding workshop",
    "active": true, "audiences": ["EXTERNAL", "STUDENT"] } ] }
```

* Validation at startup (`OptionCatalog`), failing application start with a clear message
  (AC-003-07): `id` required, matches `^[a-z0-9][a-z0-9-]{0,63}$`, unique; `name` required
  (≤ 200 chars); `category` one of the enum; `audiences` non-empty (default both if omitted).
* `OptionCatalog.activeFor(type)` → active options available to that audience.
* `OptionCatalog.resolve(type, ids)` → returns the matching options or throws
  `InvalidOptionException` listing unknown / inactive / not-for-audience identifiers
  (AC-003-03, AC-003-04, AC-002-06).

## 4. REST API

Base path `/api`. JSON UTF-8. Unknown JSON properties are **rejected**
(`FAIL_ON_UNKNOWN_PROPERTIES=true`) so variants are not interchangeable (AC-002-05).

| Method & path | Auth | Purpose | AC |
|---|---|---|---|
| `GET /api/options?type=EXTERNAL\|STUDENT` | public | active options for the variant | AC-003-01, AC-003-05, AC-002-07 |
| `GET /api/form-token` | public | issue signed anti-bot form token | AC-PC-04 |
| `POST /api/registrations/external` | public | external registration | AC-001-* |
| `POST /api/registrations/student` | public | student registration | AC-002-* |
| `GET /api/admin/registrations/export` | HTTP Basic, role `ORGANIZER` | download `.xlsx` | AC-008-* |
| `GET /actuator/health`, `/actuator/health/liveness`, `/actuator/health/readiness` | public | container health | AC-PC-09 |

No endpoint returns stored participant data except the authenticated export (AC-PC-10).

### 4.1 Requests

External (`ExternalRegistrationRequest`):

```json
{ "firstName": "Ana", "lastName": "Novak", "email": "ana@example.si",
  "organization": "FERI", "privacyConsent": true,
  "optionIds": ["ws-secure-coding"], "formToken": "<token>", "website": "" }
```

Student (`StudentRegistrationRequest`): as above but `studyInstitution`,
`studyProgramme`, `studentId` instead of `organization`.

`website` is the honeypot (must be empty or absent). `optionIds` optional (AC-003-06).

### 4.2 Responses

* `201 Created` `{ "id": "<uuid>", "type": "EXTERNAL", "createdAt": "<ISO-8601>" }`, `Location` header not set (no read endpoint).
* Error body (all 4xx/5xx from `/api`):
  `{ "status": 400, "error": "VALIDATION_FAILED", "message": "…", "fieldErrors": { "email": "…" } }`

| Situation | Status | `error` |
|---|---|---|
| Bean Validation failure / invalid option / missing consent | 400 | `VALIDATION_FAILED` |
| Malformed JSON, unknown property, wrong type | 400 | `MALFORMED_REQUEST` |
| Honeypot filled, bad/expired/reused/too-fast form token | 400 | `SUBMISSION_REJECTED` |
| Unsupported media type | 415 | `UNSUPPORTED_MEDIA_TYPE` |
| Method not allowed | 405 | `METHOD_NOT_ALLOWED` |
| Rate limit exceeded | 429 | `RATE_LIMITED` (+ `Retry-After`) |
| Missing/invalid organizer credentials | 401 | (Spring Security, `WWW-Authenticate: Basic`) |
| Anything else | 500 | `INTERNAL_ERROR`, generic message, no stack trace (AC-PC-07) |

## 5. Validation (PC §Validation and security, FS §General field rules)

Applied in the backend always; mirrored in the frontend for usability only.

1. **Normalisation** (global Jackson `String` deserializer): trim leading/trailing whitespace
   (AC-001-08) and Unicode NFC-normalise. Whitespace-only becomes empty → fails `@NotBlank`
   (AC-001-09).
2. **Field rules**

| Field | Rules |
|---|---|
| firstName, lastName | required, ≤ 100, `^[\p{L}\p{M}][\p{L}\p{M} .'’-]*$` (Unicode letters, AC-001-07) |
| email | required, ≤ 254, `@Email` + `^[^@\s]+@[^@\s]+\.[^@\s]{2,}$` |
| organization, studyInstitution, studyProgramme | required for its variant, ≤ 200, no control characters (`^[^\p{Cntrl}]+$`) |
| studentId | required (student), ≤ 50, `^[\p{L}\p{N}/-]+$` |
| privacyConsent | must be `true` (`@AssertTrue`) (AC-001-05) |
| optionIds | ≤ 50 entries, each `^[a-z0-9-]{1,64}$`, no duplicates; resolved by `OptionCatalog` |
| website (honeypot) | must be empty |
| formToken | required, ≤ 512 |

3. Messages are human-readable English per field, returned in `fieldErrors`.
4. Length limits + no control characters is the "malicious input" defence at the boundary;
   injection safety is provided by construction (§9): parameterised JPA, React escaping,
   plain-text email, text-typed Excel cells. Markup is therefore stored literally (AC-PC-01)
   in free-text fields, while name fields reject it by pattern.
5. Max request body: 16 KiB, enforced by Nginx `client_max_body_size` (413) and in the backend
   by `RateLimitFilter`'s sibling check on `Content-Length` for `/api/registrations/**` (413).

## 6. Registration processing (US-001, US-002, US-004, US-005)

`RegistrationService.register(command)` — `@Transactional`:

1. Anti-bot check (`FormTokenService.verify`) and honeypot check — before any persistence.
2. `OptionCatalog.resolve` the option ids for the variant.
3. Build and `saveAndFlush` the `Registration` (constraint errors surface here).
4. Serialise the backup JSON (`RegistrationBackup` record) and write it through
   `BackupWriter` (§7). An `IOException` → `BackupFailedException` → transaction rolls back →
   500 to the client, no success shown (AC-005-04).
5. Register a `TransactionSynchronization`: on rollback after the file was written, delete
   the file (keeps DB and backups consistent).
6. Mark the form-token nonce as used.
7. Publish `RegistrationCompletedEvent(registrationId, backupJsonBytes, …)`.

Emails are sent by a `@TransactionalEventListener(phase = AFTER_COMMIT)` running `@Async`
so SMTP latency/failure never affects the HTTP response or the stored data (AC-006-03).

## 7. JSON backup (US-005, AC-005-02, AC-005-05, AC-005-06)

* Directory `app.backup.dir` (env `APP_BACKUP_DIR`, container `/data/backups`, named volume).
  Created at startup; startup fails if not writable.
* File name `registration-<yyyyMMdd'T'HHmmss'Z'>-<uuid>.json`.
* Content: `{ "schemaVersion": 1, "id", "type", "createdAt", "participant": {fixed fields},
  "privacyConsent": true, "options": [ {"id","category","name"} ] }`, pretty-printed UTF-8.
* Atomic write: write to `<name>.tmp` in the same dir, `fsync`, then `ATOMIC_MOVE` to final name.
  POSIX permissions `rw-------` where supported (PII).

## 8. Email (US-006, US-007)

* `spring-boot-starter-mail`, SMTP settings via standard `SPRING_MAIL_*` env.
* `app.mail.from` (sender), `app.mail.organizers` (comma-separated list, ≥ 1 required at startup).
* Participant confirmation: plain-text UTF-8, subject "Registration confirmed – <conference name>",
  body with name, registration id, variant, selected options (AC-006-01, AC-006-04).
* Organizer notification: plain-text UTF-8 body with all submitted fields + attachment
  `registration-<uuid>.json` (`application/json`, exactly the backup bytes) (AC-007-01/02).
  Plain text means participant markup is never rendered (AC-007-04). Header injection is
  impossible because newline/control chars are rejected in all fields and JavaMail encodes
  subjects.
* Failures are logged (registration id only, no PII) and not retried (retry/outbox is out of
  scope; documented as an open item).
* Emails are only triggered by `RegistrationCompletedEvent`, which only exists after a
  successful commit (AC-006-02, AC-007-03).
* `management.health.mail.enabled=false` — an unavailable SMTP server must not mark the
  application unhealthy, consistent with AC-006-03.

## 9. Excel export (US-008)

* `GET /api/admin/registrations/export` → `200`,
  `Content-Type: application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`,
  `Content-Disposition: attachment; filename="registrations-<timestamp>.xlsx"`,
  `Cache-Control: no-store`.
* Apache POI `SXSSFWorkbook` (streaming). Sheet "Registrations"; header row always present
  (AC-008-03). Columns: ID, Type, Created at (UTC), First name, Last name, Email,
  Organization, Study institution, Study programme, Student ID, Privacy consent, Workshops,
  Events, Meals, Other activities (option display names joined by `; `).
* Queried at request time (`findAllWithOptions` ordered by `created_at`) → always current (AC-008-04).
* All values written as string cells; values starting with `=`, `+`, `-`, `@`, tab or CR get the
  `quotePrefixed` cell style so Excel treats them as text (AC-008-05).
* Authentication: HTTP Basic, single organizer account from env `APP_ADMIN_USERNAME` /
  `APP_ADMIN_PASSWORD` (password ≥ 12 chars enforced at startup, BCrypt-hashed in memory).
  Access is logged (username, no data). Browser usage: open the URL, enter credentials.

## 10. Frontend (React 18 + Vite + TypeScript)

* Routes (tiny internal router on `window.location.pathname`, Nginx `try_files` fallback):
  `/` chooser, `/register/external`, `/register/student`.
* Structure: `api/client.ts` (fetch wrapper, typed errors), `validation/rules.ts` (mirror of §5),
  `components/RegistrationForm.tsx` (variant-driven field list), `components/TextField.tsx`,
  `components/OptionGroups.tsx`, `components/Confirmation.tsx`, `App.tsx`.
* Behaviour:
  * On mount: `GET /api/options?type=…` and `GET /api/form-token` in parallel. Options grouped by
    category, headings only for non-empty groups (AC-003-01, AC-003-05).
  * Consent checkbox unchecked by default (AC-001-06); links to the privacy statement text shown inline.
  * Client validation on blur and on submit; invalid → no request, errors shown under fields with
    `aria-invalid` / `aria-describedby`, focus moves to first invalid field (AC-001-03, AC-002-04).
  * Submit button disabled while a request is in flight (AC-004-04).
  * Success (201) → form replaced by confirmation panel with registration id (AC-004-01). The
    confirmation is only rendered from a 201 response.
  * 400 `VALIDATION_FAILED` → server `fieldErrors` mapped to fields (AC-004-02).
  * 400 `SUBMISSION_REJECTED`, 429, 5xx, network error → general error banner, entered data
    kept, new form token fetched (AC-004-03).
  * Honeypot input `website` rendered off-screen, `tabIndex=-1`, `autoComplete="off"`, `aria-hidden`.
* Responsive: single-column fluid layout, `max-width: 40rem`, inputs `width: 100%`,
  `<meta name="viewport">`, touch targets ≥ 44 px, no fixed widths (AC-PC-08).
* No `dangerouslySetInnerHTML`; all user text rendered through React (AC-PC-01).

## 11. Security controls (PC §Validation and security)

| Control | Implementation | AC |
|---|---|---|
| Backend validation | Bean Validation + OptionCatalog, §5 | AC-001-04, AC-002-03, AC-003-03/04 |
| Anti-automation 1: honeypot | `website` must be empty | AC-PC-03 |
| Anti-automation 2: signed form token | `GET /api/form-token` returns `base64url(issuedAtMillis.nonce).base64url(HMAC-SHA256)`; secret `APP_FORM_TOKEN_SECRET` (≥ 32 bytes; random per start if unset, logged warning). Rejected if signature invalid, age < `min-fill-seconds` (default 3 s), age > 2 h, or nonce already used. Used nonces kept in a bounded in-memory map until expiry. | AC-PC-04 |
| Anti-automation 3: rate limit | `RateLimitFilter` per client IP, fixed window, atomic `ConcurrentHashMap.compute` (no check-then-act race): registrations 10 / 10 min, form tokens 60 / 10 min, admin 20 / 10 min (configurable). 429 + `Retry-After`. Client IP = `request.getRemoteAddr()` after Tomcat `RemoteIpValve` (`server.forward-headers-strategy=native`) which trusts `X-Forwarded-For` only from private-network proxies; Nginx overwrites the header with `$remote_addr`, so clients cannot spoof it. | AC-PC-05 |
| Security headers (backend) | Spring Security: `Content-Security-Policy: default-src 'none'; frame-ancestors 'none'`, `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Referrer-Policy: no-referrer`, `Cache-Control: no-store` | AC-PC-06 |
| Security headers (frontend) | Nginx: CSP `default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; connect-src 'self'; frame-ancestors 'none'; base-uri 'self'; form-action 'self'; object-src 'none'`, nosniff, `X-Frame-Options: DENY`, `Referrer-Policy: strict-origin-when-cross-origin`, `Permissions-Policy`; `server_tokens off` | AC-PC-06 |
| Authn/z | Export behind HTTP Basic (`ORGANIZER`); everything else under `/api/admin/**` denied without it; unknown paths `denyAll` | AC-008-02, AC-PC-10 |
| CSRF | Disabled: API is stateless (`SessionCreationPolicy.STATELESS`), no cookies; the only authenticated endpoint is a safe `GET` | — |
| CORS | Not enabled (same-origin via proxy) | — |
| Error hygiene | `server.error.include-stacktrace=never`, `include-message=never`; global handler returns generic bodies | AC-PC-07 |
| Data at rest | Backup files `0600`; DB credentials via env; no PII in logs | PC "secure handling" |
| Transport | TLS is terminated in front of the frontend container in production (reverse proxy/ingress); documented as a deployment requirement, not part of these containers | PC "secure handling" |
| Containers | non-root users, minimal base images, only frontend port published publicly; backend published on `127.0.0.1` only | PC §Deployment |

## 12. Error handling

* `GlobalExceptionHandler` (`@RestControllerAdvice`) maps exceptions to §4.2.
* `SubmissionRejectedException` (anti-bot) deliberately gives a generic message (no hint which check failed).
* Unhandled exceptions logged with a correlation id (`X-Request-Id` generated if absent, echoed back).

## 14. Containerised deployment (PC §Deployment, TECH_STACK §Deployment target)

* `backend/Dockerfile`: stage 1 `eclipse-temurin:21-jdk-alpine` runs `./mvnw -B package -DskipTests`;
  stage 2 `eclipse-temurin:21-jre-alpine`, user `app` (uid 10001), `/data/backups` owned by it,
  `HEALTHCHECK` via `wget /actuator/health/readiness`.
* `frontend/Dockerfile`: stage 1 `node:22-alpine` `npm ci && npm run build`; stage 2
  `nginxinc/nginx-unprivileged:1.27-alpine` (non-root, port 8080) with `nginx.conf`.
* `docker-compose.yml`: `db` (`postgres:16`, volume `pgdata`, `pg_isready` healthcheck),
  `backend` (depends on healthy db; volumes `backups`, bind `./config/conference-options.json:ro`;
  port `127.0.0.1:8081:8080`), `frontend` (depends on healthy backend; port `8080:8080`).
  Secrets from `.env` (`.env.example` committed, `.env` git-ignored). Compose fails fast
  (`${VAR:?}`) when required secrets are missing.
* `docker-compose.verify.yml` (verification overlay only): adds a Mailpit SMTP catcher so email
  sending can be observed during container verification.
